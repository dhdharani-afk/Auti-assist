# AutiAssist deployment guide

AutiAssist is a child-focused learning and communication support application. It is not a medical, psychological, or diagnostic tool. This repository keeps SQLite for local development and uses PostgreSQL for hosted deployments.

## Architecture

- Frontend: React 18, Vite, React Router, Axios, Chart.js
- API: FastAPI, Pydantic, SQLAlchemy
- Local database: SQLite
- Hosted database: PostgreSQL
- Local AI: Ollama (development only)
- Hosted AI: OpenAI-compatible Chat Completions API called server-to-server by FastAPI
- Frontend hosting: Cloudflare Pages
- API/database hosting: Render web service + managed PostgreSQL

The browser only calls FastAPI. AI API credentials and database credentials are server-side environment variables.

## Social situation practice

The existing child-protected `/social-simulator` route uses the authenticated social-simulator scenario, result, and progress APIs. Scenarios include local illustrated scenes and visual choices; voice, read-aloud, and picture-word AAC practice are recorded through the existing per-user communication log. Completion and stars continue to use the existing social result records, so this feature adds no tables or migration. If the scenario API is unavailable, previously loaded or built-in scenario content remains available for practice, but progress cannot be saved until the API reconnects.

## Local development

Create `backend/.env` from `backend/.env.example`; for local development use `AUTIASSIST_ENV=development`, a private random `SECRET_KEY`, and `DATABASE_URL=sqlite:///./autiassist.db`. Set local Ollama values (`AI_PROVIDER=ollama`, `OLLAMA_URL=http://localhost:11434/api/generate`, and `OLLAMA_MODEL=gemma3`) if using the local model.

Create `frontend/.env` from `frontend/.env.example`. Set `VITE_API_URL=http://localhost:8000`, or leave it empty to use the Vite `/api` proxy.

```sh
cd backend
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

In a second terminal:

```sh
cd frontend
npm ci
npm run dev
```

Local UI: `http://localhost:5173`; API docs: `http://localhost:8000/docs`; health: `http://localhost:8000/health`.

## Deploy the API and PostgreSQL on Render

1. Push this repository to a private or public GitHub repository. Confirm `.env` files, SQLite databases, and keys are not staged.
2. In Render, create a Blueprint from the repository and approve the resources in `render.yaml`. The Blueprint creates a paid Docker API service and a managed PostgreSQL database. Paid, non-sleeping web/database plans are required for 24/7 availability; free tiers may sleep, expire, or have limited persistence.
3. The container runs `alembic upgrade head` before Gunicorn starts. Render's managed `DATABASE_URL` is normalized to the SQLAlchemy psycopg driver.
4. Set `FRONTEND_ORIGINS` to the exact deployed Cloudflare Pages origin, for example `https://your-site.pages.dev` (no trailing slash). Do not set `*`.
5. Configure hosted AI server-side as described below. Without it, the app and non-AI features work; AI chat responds with a friendly unavailable error.
6. Check `https://<render-service>.onrender.com/health` returns `{"status":"ok","database":"ok"}` and review Render logs for migration/startup errors.

Render's `SECRET_KEY` is generated by the Blueprint. Do not replace it with a checked-in value. Restrict access to production logs because application logs may contain request paths and diagnostic details.

## Deploy the frontend on Cloudflare Pages

1. Create a Pages project connected to the GitHub repository.
2. Set the project root directory to `frontend`.
3. Set build command to `npm ci && npm run build` and output directory to `dist`.
4. In Pages environment variables, set `VITE_API_URL` to the HTTPS Render API origin, e.g. `https://your-api.onrender.com` (no `/api` suffix).
5. Deploy. The included `frontend/public/_redirects` enables React Router deep links on Pages.
6. Copy the resulting exact Pages origin into Render's `FRONTEND_ORIGINS`, then redeploy the API. If using a custom domain, set the custom HTTPS origin there instead.

Vite variables are compiled into the public frontend bundle. Only `VITE_API_URL` belongs there; never put credentials, API keys, database URLs, or JWT secrets in any `VITE_*` variable.

## Environment variables

### API service

| Variable | Required | Description |
| --- | --- | --- |
| `AUTIASSIST_ENV` | Yes | Set to `production` on hosted API. |
| `SECRET_KEY` | Yes | Unique random secret of at least 32 characters; keep only in the hosting secret store. |
| `DATABASE_URL` | Yes | Managed PostgreSQL URL in production; local default is SQLite. |
| `FRONTEND_ORIGINS` | Yes | Comma-separated exact HTTPS frontend origins; no wildcard. |
| `AI_PROVIDER` | For hosted AI | `openai_compatible` in production or `ollama` locally. |
| `AI_API_URL` | For hosted AI | Full OpenAI-compatible chat completions endpoint URL. |
| `AI_API_KEY` | For hosted AI | Provider key; store only as a hosting secret. |
| `AI_MODEL` | For hosted AI | Model name supported by the selected provider. |
| `OLLAMA_URL` | Local Ollama | Local generate endpoint; never expose it to the browser. |
| `OLLAMA_MODEL` | Local Ollama | Local model name, default `gemma3`. |
| `OLLAMA_KEEP_ALIVE` | Optional | Ollama model keep-alive duration. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Optional | Token lifetime; production default is 60 minutes. |
| `PORT` | Hosting-provided | API listener port; Gunicorn uses the platform-provided value. |

See `.env.example`, `backend/.env.example`, and `frontend/.env.example` for variable names only.

## AI provider configuration

Production defaults to `AI_PROVIDER=openai_compatible`. Set the provider's full endpoint, key, and model in the API host's secret/environment settings. FastAPI sends the AutiAssist child-friendly system prompt and conversation to that endpoint; the React bundle never receives the API key. Any provider implementing the standard Chat Completions request/response shape can be used. Ensure its data-handling terms meet your privacy requirements for a child-facing service.

For local development set `AI_PROVIDER=ollama`, start Ollama, and configure `OLLAMA_URL` and `OLLAMA_MODEL`. Production should not point Ollama at a developer workstation.

## Database migrations and existing data

Alembic migrations are in `backend/migrations`. Apply them with:

```sh
cd backend
alembic upgrade head
```

Create a future migration after model changes with:

```sh
cd backend
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
```

Review generated migration code before deploying it. Production startup intentionally does not call `create_all`; schema changes must be migrated before app workers start. Local development retains SQLAlchemy `create_all` for backward compatibility.

SQLite data is not silently copied to PostgreSQL. Before moving real child/user records, obtain appropriate authorization, make an encrypted backup, plan and test an explicit database migration, and verify user ownership/counts on the destination. Do not upload the included local SQLite file to GitHub or a public location.

## Production commands

Container build context is the repository root:

```sh
docker build -f backend/Dockerfile -t autiassist-api .
```

The container applies Alembic migrations and launches:

```sh
gunicorn main:app -k uvicorn.workers.UvicornWorker \
  --bind 0.0.0.0:${PORT:-8000} --workers ${WEB_CONCURRENCY:-2} \
  --timeout 120 --access-logfile - --error-logfile -
```

Frontend production build:

```sh
cd frontend
npm ci
VITE_API_URL=https://your-api.example.com npm run build
```

## Security and child privacy

- Passwords are hashed; JWT signing uses a host-provided secret.
- User activity routes scope records to the authenticated JWT user.
- CORS allows only configured frontend origins in production.
- Do not deploy with development credentials or expose `/docs` publicly if your deployment policy requires disabling API documentation.
- Camera frames are transient and are not stored. The optional camera page uses the bundled MediaPipe Face Landmarker task at `backend/assets/face_landmarker.task` (from Google's official MediaPipe model storage; SHA-256 `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`) plus a lightweight **demo heuristic** over its blendshapes. It is not a trained mood classifier or a reliable reading of a child's feelings; results are labeled estimated facial expressions and should not be used as a diagnosis or assessment.
- Do not store raw voice recordings. Review external AI provider data policies before enabling them publicly.
- Before public use by children, complete a privacy/legal review appropriate to your location and audience (including applicable parental-consent requirements). The app is a prototype and does not establish compliance certification.

## Validation checklist

- [ ] Production API health is HTTP 200 and reports database `ok`.
- [ ] Signup/login and `/api/auth/me` work from the deployed HTTPS frontend.
- [ ] Protected deep links redirect correctly after refresh.
- [ ] New users begin with empty progress; two accounts cannot read each other's activity.
- [ ] Learning, games, communication, routine, rewards, progress, mission, and social simulator persist across refresh.
- [ ] CORS rejects an unconfigured origin.
- [ ] Hosted AI responds with a configured key; without configuration the UI shows an unavailable state and other modules remain usable.
- [ ] Camera use is optional, permission denial is handled, and no frames are persisted.
- [ ] A PostgreSQL backup/restore procedure and monitoring are configured.

## GitHub safety checks

```sh
git status --short
git check-ignore backend/.env frontend/.env backend/autiassist.db
```

Review staged files before pushing. Never force-add ignored secrets or local databases.

This workspace currently has no Git repository configured. After creating an empty GitHub repository, use the following commands from the project root (replace the remote URL with your repository):

```sh
git init -b main
git add -A
git diff --cached --check
git status --short
git commit -m "Prepare AutiAssist for production deployment"
git remote add origin https://github.com/<account>/<repository>.git
git push -u origin main
```

If Git is already initialized when you use these instructions, skip `git init` and configure the existing `origin` instead. Do not add secrets to commit history.
